# Introduction to OSINT

## What is OSINT?

**OSINT (Open Source Intelligence)** is the practice of collecting and analyzing information from publicly available sources to build actionable intelligence about a target — a person, organization, website, or piece of infrastructure. "Open source" here doesn't mean open-source software; it means information that is legally and publicly accessible without hacking, bypassing authentication, or any unauthorized access — search engines, social media, public records, code repositories, forums, news articles, and so on.

OSINT sits at the heart of the Reconnaissance/Footprinting phase — in fact, most of what's covered under "Footprinting" (search engines, social networking sites, website footprinting, email footprinting) are really specific *techniques* within the broader discipline of OSINT. OSINT is also its own standalone field used well beyond hacking — by journalists, law enforcement, corporate threat-intel teams, and researchers — because the skill of finding and connecting public information has value everywhere.

The core principle: **everything gathered in OSINT is already public.** No system is touched, no authentication is bypassed, no vulnerability is exploited. The "hacking" here is in the skill of searching, correlating, and connecting scattered pieces of public data into a complete, useful picture — not in breaking into anything.

---

## Objectives of OSINT

1. **Identify IP addresses, subdomains, ports, and services that increase the attack surface**
   Every subdomain, exposed port, or forgotten service discovered through OSINT is a potential entry point discovered before any actual scanning tool touches the target.

2. **Identify technologies used, application platform, and infrastructure details**
   Knowing the CMS, programming language, cloud provider, or hosting setup lets a pentester later look up known vulnerabilities specific to that stack instead of guessing blindly.

3. **Identify sensitive information exposure**
   This includes leaked **API keys**, exposed **AWS S3 buckets**, and **leaked credentials** — these are some of the most damaging findings OSINT can surface, since they can lead directly to unauthorized access without any exploitation at all.

4. **Identify other exposed data**
   Log files, backup files, database files, client-side code, JavaScript libraries, and configuration files — all of these can leak internal structure, credentials, comments left by developers, or outdated dependencies with known vulnerabilities.

---

## Categories of OSINT

### 1. Passive OSINT
Gathering information entirely through third-party sources (search engines, WHOIS databases, social media, breach databases) — the target's own systems are never touched, so there's zero detection risk.

### 2. Active OSINT (borderline)
Some OSINT techniques involve lightweight direct interaction with the target — e.g., visiting the live website to check response headers, or using a tool like `theHarvester` in modes that send DNS queries. This is still legal and low-risk, but technically does touch the target's infrastructure, unlike pure passive OSINT.

## Major OSINT Categories & What They Uncover

| Category | What It Reveals |
|---|---|
| **People/Employee OSINT** | Names, roles, email formats, social media activity, personal habits (LinkedIn, Twitter/X, Facebook) |
| **Infrastructure OSINT** | IP ranges, subdomains, DNS records, network topology, hosting provider |
| **Technology OSINT** | CMS/framework/library versions, server software, cloud provider fingerprints |
| **Code/Repository OSINT** | Public GitHub/GitLab repos — leaked secrets, internal logic, outdated dependencies |
| **Document OSINT** | PDFs, Word docs, spreadsheets — metadata (author, software version, GPS tags), internal file paths |
| **Breach/Credential OSINT** | Leaked passwords/emails from past breaches (HaveIBeenPwned, Dehashed) |
| **Financial/Business OSINT** | Company filings, job postings (which leak tech stack requirements), press releases, partner/vendor relationships |

## Core OSINT Tools

| Tool | Purpose |
|---|---|
| `theHarvester` | Emails, subdomains, hosts from public sources |
| **Maltego** | Visual link-analysis tool — maps relationships between people, domains, IPs, and organizations |
| **Recon-ng** | Modular recon framework — automates many OSINT source lookups in one place |
| **Shodan / Censys** | Internet-wide device and service search |
| **SpiderFoot** | Automated OSINT aggregation across 100+ data sources |
| **FOCA** | Metadata extraction from public documents |
| `sherlock` | Username enumeration across social media platforms |
| `holehe` | Checks which platforms an email is registered on |
| **Google Hacking Database (GHDB)** | Pre-built search-engine dorks by category |
| **Wayback Machine** | Historical snapshots of websites, deleted/forgotten content |
| **crt.sh** | Certificate transparency logs — reveals subdomains via SSL certificate records |

## OSINT Methodology — A Practical Flow

1. **Define scope** — decide exactly what/who is being investigated, and confirm it's authorized
2. **Start broad** — company website, "About Us," job postings, social media presence
3. **Narrow to infrastructure** — WHOIS, DNS records, subdomain enumeration
4. **Dig into people** — employee names/roles via LinkedIn, cross-reference with email-pattern tools (Hunter.io)
5. **Check for exposure** — breach databases, exposed repos (GitHub dorking), misconfigured cloud storage
6. **Correlate everything** — connect findings into a single profile (Maltego is built exactly for this step)
7. **Document** — organize findings clearly, since this feeds directly into the next phase (Scanning)

---

## Ethical & Legal Note

Even though OSINT only touches public data, the same rule applies as with every other footprinting technique: gathering the information is legal, but **acting** on sensitive findings (using a leaked credential, accessing an exposed S3 bucket's contents) without authorization is not. In a professional engagement, OSINT is always scoped to a signed agreement — outside of that, practice only on your own accounts/domains or explicitly legal targets like GHDB entries or lab environments.
